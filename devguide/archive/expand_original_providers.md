# Original-provider consolidation and expansion

## What

The maintainer selected this work before further BenchLab development. Keep
the existing five provider families and implement four additional original
engines, preserving their different scientific result objects.

## How

Follow [the maintained implementation plan](../external_provider_expansion_plan.md).
Independent implementation owners are pyKVFinder #136, GHECOM #137, CAVER #138
and P2Rank #139. Handoff #101, exhaustive fidelity #19 and qualification
#16/#58/#81 retain their separate scopes.

## Why

Controlled comparisons need trustworthy original results, useful public
interfaces and reproducible recovery before they can guide native DFND studies.
Catalogue membership or successful parsing alone does not qualify execution.

## What was refuted

Do not convert channel paths or predicted binding sites into closed pocket
volumes. Do not treat free academic editions as universal open-source licences.
MOLE's Linux build and POVME3's documented Python-2-era route require further
assessment; neither is claimed as an executed provider by this batch.

## Scope and exclusions

No paid route, unsolicited remote coordinate submission, new native DFND
protein characterization or automatic comparison/superiority claim.
Development source checks do not establish installed/public release delivery.

## Acceptance criteria

- Extensible catalogue with explicit access/licence and evidence levels.
- Four original adapters with execution, original artifacts, scientific
  semantics, source context, quantities and engine-independent recovery.
- Small direct-upstream comparisons plus valid-empty, malformed, absent-engine,
  source mismatch and resource-control checks.
- Existing-provider regressions remain passing; unresolved external service or
  package limitations remain explicit and owned.

The bounded source milestone satisfies these criteria. All four new original
implementations have real source execution and retained/recoverable evidence;
the five older saved-provider families retain passing regression controls.
pyKVFinder's separate compatibility fork has native and tomlkit floor/current
evidence without changing its scientific kernels. The guard reconstructs exact
original output from all four additions; direct execution gates and resource
scope are recorded in the checkpoint. The source batch can now hand back to the
synthetic BenchLab sequence. Existing CASTp availability, #101 installed
receiving, exhaustive fidelity #19 and release/CI #16/#58/#81 remain separate.
