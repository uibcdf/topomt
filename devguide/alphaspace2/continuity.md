Updated exact installed qualification and dependency-origin verification remain

## Historical native evidence

The older [native checkpoint](native_checkpoint.md) retains the detailed
geometry, grouping, scoring and contact investigation. Its `0.3.0` scheduling
language is historical. The implemented native work includes alpha/beta state,
lining-atom recovery, grid/overlap helpers and optional contact propagation;
typed Vina-aware scoring has a bounded CDK2 reference case. Historical green
examples do not prove complete nonpolar, typing, scoring, binder or input-domain
fidelity.

The [native contract](contract.md) and existing
[parity tests](../../tests/methods/alphaspace2/test_parity.py) preserve the chosen
reference and tolerances. If native scoring/table/contact work is explicitly
selected, its focused existing guard can be run in the qualified environment:

```bash
python -m pytest --receptor=llm \
  tests/methods/alphaspace2/test_parity.py -k 'beta_probe or cdk2'
```

That selector covers helper/CDK2 scoring rather than all contact or original
receiving behavior. Read fixture requirements and account for unavailable
original packages or upstream datasets; skips do not qualify the omitted route.
The native plan and scientific parity gaps remain separate from original
execution, persisted recovery and consumer-model qualification.

## Development boundary

Original and native routes retain their own signatures, quantity semantics and
validation scopes. The original route already uses ArgDigest for name/value
admission; an old note suggesting that this rollout is still waiting for a
bare-float policy is obsolete. Consult the actual facade/digesters and registered
[ArgDigest guide](../../ARGDIGEST_GUIDE.md), rather than introducing a new default
unit or bypass from these historical notes.

Use public MolSysMT operations for molecular representation, chemistry, selection
and geometry, PyUnitWizard for explicit conversions, and PharmacophoreMT for
recognition/modeling. A historical suggestion to move a helper is not an accepted
cross-component API or permission to copy sibling functionality. Reuse the
supported owning tools and retain the native/provider distinction described in
[the architecture](../third_party_architecture_adr.md) and
[deferred native-method plan](../native_methods_plan.md).
