# Reviewed environment tools

The owner CLI delegates to optional shared operations at immutable MolSysSuite
`8f00e6d9de943b6e4710ea62936e2ebea00fad24` (406 hosted central tests).
Set `TOPOMT_SUITE_ROOT` to that clean SDK checkout, or put it at `.molsyssuite`.
The loader verifies the actual SDK commit and administrative import origin.

```bash
python devtools/broadcast_requirements.py --check
python devtools/broadcast_requirements.py
python devtools/conda_env_manager.py create \
  devtools/conda-envs/development_env.yaml --python-minor 3.14 \
  --manager mamba --name topomt-dev
conda activate topomt-dev
python devtools/conda_env_manager.py update \
  devtools/conda-envs/development_env.yaml --python-minor 3.14 \
  --manager conda --prefix "$CONDA_PREFIX"
```

The local profile selects **five** ordinary outputs: production, development,
docs, setup and build. Runtime comes from metadata, local tooling lists contain
tools, and shared source/context checks own provenance constraints. Recipes,
release plans, fixed Git inputs, three specialized scientific test documents and
the historical importable fixture are outside generation. All selected outputs
are validated before writing; `--check` never writes. Retained selectors/channels
cannot silently widen. Source-free declarations do not imply an actual solve.

Create requires a new unoccupied name and an explicit Conda/Mamba executable.
Update requires the actual active prefix and its interpreter. There is no implicit
prune, temporary YAML in the owner tree, failed-create/update fallback or
manager operation at import time. Routine development uses the complete 3.14
minor. Scientific source environments additionally require a matching reviewed
minor; missing context/origin evidence fails rather than changing a Git revision.

The old `dev`, automatic YAML/manager discovery, `--env-name`, `--env-yaml`,
`--python` overrides and implicit editable installation are retired. Use the
explicit commands above, activate, then install the intended local source with
`python -m pip install --no-deps --editable .`. Optional kernels are separate
user actions. No scientific package API has changed.

This workspace still uses the qualified `molsyssuite@uibcdf_3.14` environment.
After a real owner environment operation, check `pip check`, import origins,
installed dependency bounds and the actual selected context with
`devtools/check_dependency_routes.py --context NAME`, then run the owner's
applicable science/native tests. A passing manager exit or administrative guard
is not that evidence. Conda scientific tests retain their existing native tools,
optional integrations and source pins; they are not regenerated by this CLI.

`nglview` is development/test/docs tooling after the maintainer's explicit
classification; it is not package or production runtime. Public core metadata
and its optional extras remain owner-defined. Optional original engines retain
[their separate requirements](../../docs/content/user/third_party_engines.md).
