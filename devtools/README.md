# Development and publication tools

Environment generation and explicit Conda/Mamba management use the qualified
optional shared operator; [conda-envs/README.md](conda-envs/README.md) gives the
commands and migration from the legacy helpers. Metadata owns runtime,
`environment_tools.toml` selects five ordinary documents and `requirements.yaml`
contains owner tools. Generation does not rewrite scientific test files, recipes,
plans or fixed Git source inputs.

[conda-build/README.md](conda-build/README.md) describes the guarded noarch route.
`check_dependency_routes.py` delegates declaration/context preflight to the
immutable SDK. Run the actual installed-context check before science; a source
inventory or administrative success does not establish scientific/public closure.

Routine workspace development uses `molsyssuite@uibcdf_3.14` and
`python -m pip install --no-deps --editable PATH` for eligible local clones.
Contributions follow the root instructions and synchronized suite guide. External
PRs and releases retain their mandatory exact-candidate gates; authorized internal
direct pushes retain the common checkpoint/recovery rules. Scientific repairs,
optional-engine selection and release version/access decisions remain owner work.
